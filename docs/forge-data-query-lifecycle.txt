2026-10-24 — automatic refresh replaces the manual-only policy below

Removed the shared Refresh report banner. Report snapshots revalidate when stale
(5 minutes) on mount, focus and reconnect. Inactive comparison observers stay
disabled; compatible owner/job/date scopes share private memory caches.

Clocked labor uses useReportShifts: initial authoritative scoped snapshot, then
30-second recent-window replacement (last 2 days within selected dates) plus
older unfinished punches fetched by ID in batches of 100. Successful complete
polls replace covered rows, catching recent voids/removals as well as inserts.
Failed/cancelled batches do not commit partial results; a newer snapshot wins.
Recent updates preserve the authoritative snapshot timestamp.

Finite ranges up to 45 days reconcile every 5 minutes. Larger/all-history ranges
have no full-history timer; old closed corrections require stale revalidation on
return/focus/reconnect or the existing ledger refresh action. No universal change
cursor has been verified, so this does not claim arbitrary old edits are immediate.
Other report readers regain automatic stale revalidation, not frequent broad polls.

Next backend investigation: a verified change cursor covering edits, deletes,
voids and job reassignment, or invalidation events followed by scoped reads.
No schema change or production operation was made for this implementation.
