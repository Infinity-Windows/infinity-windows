# Held activity totals and selected-unit Data slice

0845 is an additive, read-only candidate ending in `ROLLBACK`. It is not installed, activated, or a complete Work/Data release. It depends on the exact frozen 0844 cancellation source (`e32122a581bf995857983cc433323bc490381b6eb217c583bf95fd7376b3e53f`). No 0841–0844 body is edited. The new indexes add ordinary index maintenance; no payroll callback, review counter, new advisory class, or payroll refusal is introduced.

## Meaning and window

`work_activity_totals_read(project_id uuid, unit_id uuid default null)` returns protocol 1. With no unit it shows General activities originally captured for the selected job. With a unit it shows Specific activities captured for that unit's retained incarnation/history. Both windows are **all retained selected-scope history**, not the current date or pay period. Personal amounts include only the fresh actual authenticated actor; scope amounts include authorized recorded workers. Stable definition and version IDs retain the historical labels, including retired definitions. Machine amounts are subsets of their parent activity, never additive timers.

Amounts are exact decimal integer strings in microseconds. `asOf` comes from the server after G/7710 admission. Closed historical intervals never grow. The final open interval accrues only for the actual actor with a unique open shift, clean and matching state/transition, matching current source, no pending operation/safety condition, and an unexpired shift cap. Another worker's unfinished final interval is never extrapolated.

An available reply contains `totals` with `asOf`, `actorId`, `projectId`, nullable `unitId`, explicit `window`, `complete`, `personalComplete`, `activities`, `scopeKnownMicros`, `personalKnownMicros`, `reconciliation`, and `cohort`. Each activity has identity/version/labels/retired/scope, `personal` and `scopeTotal` quantities, and `machineSubsets`. A quantity carries `state: known|partial`, nullable `microseconds`, and `knownMicros`; personal additionally has `includesLive`. Partial means a known captured subtotal, not a complete payroll allocation. An unresolved scope may have zero known microseconds while still being unknown.

Unavailable is exactly `{ "protocolVersion": 1, "availability": "unavailable", "totals": null }`. Missing/hidden/incompatible/over-budget sources share this shape; no IDs, digests, counts, or hidden-source details precede authorization. Invalid session/isolation admission retains the existing authority errors.

## Reconciliation privacy

`reconciliation.scope` is required: `personal` or `authorized_scope`. Activity scope totals remain visible under their existing job/unit permissions. Payroll gross/paid/break amounts, ledger counts, adjustments, unresolved-scope flags and safety/review issues are stricter: callers receive only their own ledgers unless fresh `final_qc` authority covers the selected scope and every included ledger's current/original dependent job, opening, service and captured-fact context. A grant on the selected job alone does not expose a differently allocated/original job's reconciliation. The cohort also requires `authorized_scope`; missing dependent authority makes it unavailable/role_restricted and can never produce eligible=true.

An installer with no own ledger gets `scope: personal`, ledgerCount0, null gross/payroll, zero other known amounts, no coworker issues and no coworker unresolved-scope flag. Own safety/review evidence remains visible to that installer. A currently granted foreman receives the permitted aggregate. No second clock or raw payroll grant is introduced.

## Proof and reconciliation

The reader retains the existing READ COMMITTED → G7712 → actual actor →7710 → fresh actor order. It derives one effective interval from each actual transition state. Typed companion/phase children corroborate the effective source and are never added as more clocks. Closed payroll, source identity/interval changes, profile identity changes, source reuse, broken causal history, overlapping payroll, missing transitions and reviewed exceptions remain partial/untrusted.

A custom capture requires a real applied server activity command, its original transition and source birth, immutable definition/menu selection metadata, original project/unit identity, and captured fact/incarnation. Break return requires the actual server break-end transition linking the resumed source to its predecessor, all the way to that original command. Metadata equality alone is insufficient. Current and retained original job/opening/service/fact grants are checked before any result. No profile alias is guessed; identity changes are unproven. Fully erased privileged maintenance remains an explicit procedural boundary; reenabling a trigger cannot recover lost history.

Reconciliation records exact gross, classified, setup, explicit unclassified, placed-break elapsed, scalar payroll break deduction, and `policyAdjustmentMicros = placed break − deduction`. The gross partition must agree. A scalar deduction is never spread across activities. Rounding/unplaced deduction differences are visible adjustments and exclude trusted inclusion. Unbound legacy work sets `unresolvedScope`; unknown intervals are not synthetic zero or fake allocations. A named recorded subtotal may remain known while an explicit no-task gap is separately visible. Trusted inclusion still requires the entire relevant ledger's classified/setup/gap/break/payroll proof and no unclassified gap.

**Cross-job capability limit:** frozen 0841 rejects a switch whose selected job differs from the current payroll allocation. Actual authenticated `edit_shift` A→B marks its custom sources `review_required`; 0845 correctly excludes these reviewed intervals even though their immutable original capture still identifies A. The reader does not use project equality as a substitute for capture lineage and does not erase review flags. Supporting explicit mid-shift job changes requires a separate reviewed capture transition contract: preserve one uninterrupted paid shift, authorize both original/current job scopes, close/open activity sources at one chosen timestamp, retain immutable original job and fact bindings, and reconcile any payroll correction explicitly. This is a full-goal release gate, not implemented by this read slice.

## Trusted Data cohort

This first cohort is **one explicitly selected unit**. The reader calls the exact 0844 scope/view once, avoiding N selected units × global scope scans. Eligible labor and area use the identical single eligible-unit list. Required conditions: current independent dimension verification, actual current accepted QC, quiescent/no-rework unit, positive attributed labor, complete source/payroll proof, approved closed payroll, no unclassified gap or break adjustment. Reopening QC or later work removes trusted inclusion while preserving known recorded subtotals. General overhead remains separate.

Area is transported as an exact rational square-foot numerator/denominator: inch=1, foot=12, mm=5/127, cm=50/127, then divide square inches by144. Area is counted once for the eligible unit. The original dimension source remains separate from verification. Floor labels are returned as **unallocated**; a free-text story label does not prove single-level versus multilevel area allocation. Wider cohorts, floor allocation, representative-person rollups and legacy reconciliation remain required later work.

## Source, security and bounded cost

Private helpers deny PUBLIC/anon/authenticated/service_role; only the RPC grants authenticated execute. Its own SQL-canonical catalog hash covers function bodies/owner/config/volatility/ACLs, table columns/owners/RLS/ACLs, triggers, constraints and policies, plus the frozen 0844 guard body. Unknown catalog drift refuses totals. It does not loosen the existing review guard. Source history follows immutable predecessor edges, not timestamps or transaction IDs. Missing/forked/legacy/cyclic/ambiguous history cannot supply proven elapsed.

Column access is attested separately from table access. For every watched source table and the live-source view, the canonical `columnAccess` category checks effective SELECT, INSERT, UPDATE and REFERENCES using `has_any_column_privilege` for anon, authenticated and service_role. Effective rights include existing table grants, inherited role membership and PUBLIC grants. Existing legitimate employee rights retain their expected values; on private safety, all twelve expected client-role/privilege combinations are false. A real column-only grant changes this category even while `has_table_privilege` remains false, and the reader returns generic unavailable. No column access is granted or revoked by this correction.

PostgreSQL's existing `REVOKE ALL ON TABLE ... FROM service_role` also removes that role's explicit column grants. A new installation preflight therefore refuses any explicit service-role column ACL on the private safety table **before** its known table-default normalization. It refuses even when all seven known table privileges are present, so table grants cannot mask a column grant that would otherwise be erased. Unknown anon/authenticated/PUBLIC column grants are untouched and fail the final exact effective-access guard. This is a refusal boundary, not a claim that the provider previously had no column ACLs. Actual provider/current PostgreSQL17 attestation must be rerun for the corrected candidate.

Catalog parity is semantic across PostgreSQL17 and18. Both attest `pg_attribute.attnotnull`. PostgreSQL18 additionally stores table NOT NULL rows in `pg_constraint`; those duplicate rows are normalized into per-column validation, enforcement and NO INHERIT flags (PostgreSQL17 equivalents true/true/false). Constraint names for this duplicate representation are not authority. Every other constraint remains exact, including CHECK definitions containing `IS NOT NULL`. An unvalidated or NO INHERIT required constraint still refuses. The guard uses one indexed lateral lookup per column for these flags.

The actual full-SHA provider diagnostic run37228844274 at `c47f8824367b0ab3be195dfc4542c28a325529cc` identified only320 absent PostgreSQL18 table NOT NULL catalog rows and seven unintended service-role privileges on `work_activity_safety_events`. Existing SECURITY DEFINER safety writers retain owner access; no writer body or global default privileges change. The fixture reproduces the observed seven grants before installation, proves all seven absent afterward and confirms owner access. A subsequently restored raw grant refuses coverage. This closes a real ACL omission rather than accepting it as harmless drift.

A subsequent genuine PostgreSQL17 run admitted the normalized columns/constraints/table ACLs but found34 function EXECUTE differences. Rather than grant private helpers to make the test pass, held0845 explicitly denies service_role on31 newly created private0841 helpers and three new employee entries: work_activity_snapshot, work_activity_command and only the12-argument paid-setup clock_in overload. All signatures were matched to authored0841 declarations/revokes. No existing11-argument payroll RPC or its ACL changes. Internal owner calls and authenticated employee grants remain intact.

## Required wider-cohort expansion

The next additive service should accept a bounded explicit unit set, materialize the common live/source-history/transition relation **once under the same G/7710 admission**, and derive an OLD/NEW/current closure per selected unit. Keep original opening/service mapping edges, captured facts/incarnations, current/original permissions and retained review manifests. Aggregate labor and exact area from that same final eligible set, counting each unit area once and keeping General overhead separate.

This is a proposed next implementation, not a claim that calling the single-unit RPC N times is acceptable. Before shipping the batch service, execute genuine active-clock-wait benchmarks with simultaneous large live/history/transition relations and choose explicit batch/statement/latency bounds. No new mutable manifest pointer, payroll hook or global counter is required. A materialized local read relation is safe only after exact permission/history/currentness equivalence is established; a narrower ad-hoc filter is insufficient.
