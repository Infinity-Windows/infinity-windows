# Dormant activity capture foundation

This slice preserves the existing clock routes and all existing timed sources. It adds private inactive tables for stable activity/menu versions, explicit job management capabilities, personal revision state, immutable command outcomes and lifecycle evidence. It installs no timing-source callback or serialization gate, adds no capture RPC, seeds no active state, and grants no raw access to authenticated/anonymous clients. Company publishing and job-management APIs are not enabled.

Published menu membership is one validated immutable JSON snapshot; adding a child row cannot change an old published version. Definitions and versions retain distinct IDs. Original subject/project/source UUID evidence is preserved without operational deletion cascades; future read APIs must check present source authority before returning it. The three job-scoped evidence tables remain in the sandbox census with the standard armed guard. The purge check explicitly recognizes their retained-history disposition; unknown new scoped tables still fail. Retained grant rows are private audit evidence and never sufficient authority for a missing/deleted project. Generic database-merge planning registers all ten stable identities but refuses runnable capture inserts for any nonempty source or target, including count-only inventories. Original evidence/version/revision graphs require reviewed content-aware reconciliation. Private synthetic fixtures occur only in disposable tests/forced rollback.

The unused browser journal has its own IndexedDB database (`iw-work-capture-journal-v1`, version1). It never opens the existing `wops-write-outbox` version2. An append reads the durable head and indexed tail and writes an immutable command/new head within one native transaction. It refuses malformed/missing/conflicting tail evidence. Owner/device isolation is enforced in reads and receipt writes. A durable clientGeneration is reused in one stream; resetting the journal produces a new generation. Sequence begins0 and matches the private SQL substrate.

Plain known-field JSON is cloned before waiting for storage. Identical retries retain the original request ID and sequence; conflicting requests refuse. Unconfirmed sent commands remain pending for lost-response retry. Writes resolve only after transaction commit and reject aborted transactions. Readiness requires a confirmed immediate predecessor with matching owner/device, sequence and stream generation. Rejected predecessors remain blocking; no automatic rebasing occurs.

Receipt storage is an overlay, not authenticated proof of acceptance. Before any dispatcher is enabled it must bind the exact server result to command/actor/subject/payload/revisions/predecessor, capture the current sign-in mark and exact session token, and validate the server global CAS. New break/out requests must never depend on an uncertain activity command. No journal dispatcher/UI imports are enabled here, so no new one-personal-activity, payroll lifecycle, dimension verification, QC or cross-device guarantee is claimed.

The retained custom-work sender now binds its RPC to the verified owner's token and checks auth generation around refresh/send/result. A late result stays queued under the same original request ID for that owner to retry. This corrects account switching without changing the server action signatures, receipt IDs, clock policy or payroll.

Validation: unit tests exercise malformed input/storage refusal; native browser tests exercise durable transactions, concurrent appends, reload/abort/corrupted-tail refusal and byte-identical synthetic photo preservation in the existing v2 outbox. The source-driven PGlite migration harness checks real private grants/RLS, immutability/menu/state/receipt constraints and unchanged fixture payroll/source snapshots. 84 disposable SQL checks and the targeted purge/auth/journal tests passed locally. Actual-schema candidate-bound rollback and full required CI remain release gates. Native browser ordering is not a multi-device/server race proof. Active capture still requires the separately reviewed complete legacy entry/trigger/ACL closure, coordinated cutover and two independent PostgreSQL backend tests. Physical iPhone/weak-signal work remains a field gate.
