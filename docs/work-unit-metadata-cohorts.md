## Client receipt recovery and filtered summary contract

A command/replay receipt is an immutable historical outcome only. Never install its returned revision as current classification authority. After a measurement, binding change, delayed response or receipt recovery, obtain a fresh `work_unit_metadata_read`; its `classification.state` and `classification.revisionId` determine whether the receipt's revision is still current. A different revisionId means it has been superseded; `noncurrent` means the retained binding is no longer valid even if its revisionId matches. Measurements may leave classification current while invalidating floor proof. A binding A→B→A may leave the old receipt readable but classification Noncurrent. Incarnation mismatch refuses old receipts. No automatic resend or new command UUID substitutes for receipt recovery.

`summary.actualKnownMicros` and `summary.rawKnownArea` include only `units` with `selected=true`, including selected units that fail physical/trusted eligibility. `summary.laborMicros`, `summary.area` and trusted groups use only selected eligible units. Thus actual-minus-trusted compares the same filtered inventory, with different evidence requirements. Without filters, every current unit is selected and original whole-inventory behavior is preserved. Known-version filters exclude Unknown and Noncurrent classification from both scopes; filters never skip required source/origin proof.
