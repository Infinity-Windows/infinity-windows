## Horizon has

`capacitor.config.ts`, iOS/Android projects generated by
`scripts/cap-setup.mjs`, `lib/native/` (camera via Capacitor camera + PHPicker,
FCM push, background geolocation scaffold, deep-link auth),
`mobile-build.yml` validating the Android build on every push. Status in
`docs/mobile-ship.md`: PAUSED; crews use the PWA. Background GPS collection is
disabled; `timecardVerification.server.ts` turned every GPS-derived timecard
flag off as noise.

## Forge has

PWA only. Push on iOS works only after Add to Home Screen; the photo picker is
the limited web one; #536's camera/GPS work was PWA workarounds.

## Why not yet

- Horizon built it and shelved it. The payoffs (native picker, reliable push,
  background GPS) did not survive contact with the field, and the store
  release process is a standing cost.
- The one-app principle does not require a store app; it requires one app.

## What to take anyway

- `usePhotoCapture` as the single sanctioned capture path with a telemetry
  breadcrumb of which path ran (Forge's `PhotoCaptureSheet` is close; add the
  breadcrumb to ticket 06's telemetry).
- If a store release is ever wanted, start from Horizon's `cap-setup.mjs` and
  `mobile-build.yml`, and keep the remote-URL load strategy so deploys stay
  merge-driven.

Reopen when the owner asks for an App Store or Play listing.
